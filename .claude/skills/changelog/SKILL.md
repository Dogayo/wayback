# Запись в CHANGELOG

CI читает `CHANGELOG.md` дословно и подставляет секцию версии в GitHub Release.
Формат — часть контракта сборки, не стилистика: отклонение роняет прогон.

## Порядок действий

1. Определи, что изменилось: `git diff main...HEAD --stat`, затем `git log main..HEAD --oneline`.
   Не выдумывай пункты — только то, что реально в диффе.
2. Реши, куда писать:
   - изменения ещё не релизятся → в секцию `## [Unreleased]`;
   - готовится релиз → заведи `## [<x.y.z>+<build>] - <YYYY-MM-DD>` и перенеси
     туда накопленное из `[Unreleased]`, оставив `[Unreleased]` пустым.
3. Новые секции ставь **сразу под `[Unreleased]`** — порядок от новых к старым.
4. При релизе версия в заголовке обязана совпадать с `version:` в `pubspec.yaml`
   и с subject коммита `build(<target>): <x.y.z>+<build>`. Расходятся — CI падает
   до сборки. Правь оба файла в одном коммите.
5. Дату бери текущую, UTC, `YYYY-MM-DD`.

## Формат

```markdown
## [1.1.0+2] - 2026-09-01

### Добавлено

- Экран истории посещений.

### Исправлено

- Падение при открытии пустой ссылки.
```

Разделы — только эти, в этом порядке, пустые не пиши:

`### Добавлено` · `### Изменено` · `### Исправлено` · `### Удалено` · `### Безопасность`

## Как писать пункты

Коротко: одна строка, до ~10 слов, без точки в конце не нужно — точка ставится.

- Глагол в прошедшем времени, средний род: «Добавлен», «Исправлено», «Убрана».
- Пиши, что изменилось **для пользователя**, а не как это сделано в коде.
- Один пункт — одно изменение. Не склеивай через «и».
- Без ссылок на файлы, классы, номера коммитов.
- Без маркетинга и оценок («значительно улучшено», «теперь удобнее»).

Хорошо:
- `Добавлен поиск по истории.`
- `Исправлено зависание при потере сети.`

Плохо:
- `Отрефакторен HistoryRepository, вынесен в отдельный слой.` — внутреннее, пользователю не видно.
- `Куча мелких фиксов и улучшений.` — не говорит ничего.
- `Добавлен поиск и сортировка, а также исправлен баг с датой.` — три пункта в одном.

## Что не попадает в чейнджлог

Изменения, невидимые снаружи: рефакторинг, форматирование, правки CI,
обновления зависимостей без эффекта для пользователя, тесты.
Если после фильтрации не осталось ни одного пункта — так и скажи
пользователю и не создавай пустую секцию: CI отвергает пустую секцию версии.

## Проверка перед завершением

- Заголовок ровно `## [<версия>] - <YYYY-MM-DD>`, версия без `v`.
- Секция непустая.
- Версия совпадает с `pubspec.yaml`.
- Прогони извлечение так же, как это делает CI:

```bash
awk -v ver="## [1.1.0+2]" 'index($0, ver)==1 {f=1; next} f && /^## \[/ {exit} f {print}' CHANGELOG.md
```
